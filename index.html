On-chain contracts (testnet, chain 84257)

OracleVerifier: 0xa932ffe6e39e967e07ede70d4728f308e9d83411. It verifies the signed reports and also stores them, so read prices here.

OracleAdmin: 0x2fd2a3ecd6c74c6f42db8075fe5807eb83275124. It holds the roles, the active epoch and the feed config.

Feed IDs: BTC/USDC 0x5a156200d5ecdc327279bfb6a5c10d46bdd2446a5a231a97cdb68b268d6f547f, ETH/USDC 0x67753308930ff5782f387f68e81e084331f64d11baa04277695df0a1047fd279.

Chainlink-style AggregatorV3Adapter contracts (8 decimals, latest round only). Each one reads from the OracleVerifier above: BTC/USDC 0xcccf0424d8e4a6d96d28116bbfe211e7485a98b8, ETH/USDC 0x8dc675e403749095441181b18961e6ec12789c48.

Read an adapter with latestRoundData(). It returns a price only while the OracleVerifier says that price is usable. When the price is too old or the feed is not usable, the call reverts with ExpiredReport, UnusableFeed or NoDataPresent, so it never returns a stale price. Treat a revert as "no price right now". startedAt and updatedAt are the observation time in whole seconds. getRoundData() answers only for the current round id, and latestUsableUntil() gives the second when the current price stops being usable.

Authentication

Every request needs an API token in the header Authorization: Bearer <token>. The WebSocket upgrade at /v1/ws needs the same header.

Getting an API token

Tokens are not self-service. Tickr issues one token per consumer, so each consumer can be revoked on its own. To get one:

  1. Ask your Tickr contact for API access and name the team or service that will use it.
  2. Tickr sends you the token over a private channel, together with the API address and the CA certificate to pin.
  3. Send it on every request as Authorization: Bearer <token>, and on the WebSocket upgrade at /v1/ws.

Keep the token secret. If it leaks, tell your Tickr contact, who revokes it and issues a new one.
