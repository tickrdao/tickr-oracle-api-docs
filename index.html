Connect

Only testnet runs. There is no dev environment.

  • REST: https://<testnet-api-hostname>:8443/v1/...
  • WebSocket: wss://<testnet-api-hostname>:8443/v1/ws

The API is reachable only inside our cloud network (VPC), so your client host must be inside it. The hostname has no public DNS record, so each client host maps it to the API host's private address. Ask the oracle owner for the hostname and the address.

Always connect by the hostname, not by the address, because TLS checks that the hostname matches the certificate.

Authentication

The oracle owner sends you a token separately. Send the header Authorization: Bearer <token> on every /v1 request, including the WebSocket upgrade at /v1/ws. Browser WebSocket clients cannot set this header, so connect from a server-side client.

Never put the token in a URL, a subscribe frame or a log.

Prices

priceWad always has 18 decimals: the price is priceWad / 10^18. In JSON it is a decimal string, not a number, so parse it as a 128-bit integer, never as a float.

Example: "62417250000000000000000" = 62417.25.

Limits

  • Each signed report is valid for 3 s.
  • An update becomes due when its price moves 5 basis points or more, when its status changes, or when 1000000 µs (the heartbeat) pass without an update. Each of these makes an update due, and the relayer aims to land a quiet feed's update within one heartbeat. It flags an update as late when it was observed more than one heartbeat after the last landed update was observed. The max wait is only a start-up ceiling on the heartbeat.
  • Requests: 100 HTTP requests per second in total, one budget shared by all clients. More than that returns 429.
  • Connections: 64 open connections in total, HTTP and WebSocket together. Up to 32 subscriptions per WebSocket connection, and at most 100 frames per second from each connection.

Use the WebSocket for live prices. If you poll HTTPS, poll no more than once per second per service. On 429, back off with jitter and don't retry in a tight loop. These limits are shared, so use one connection per service, not one per thread.

Verify a report

The API never checks its own signatures, so check every report yourself before you act on a price. Pin the signer, the chain id and the verifier from this page, never from an API response. The signer is 0xf78c522598a39d78e594a4815b2f4821d1cab79f, which is activeSigner() on the OracleAdmin below.

Hashing rules

  • Domain: TickrOracle, version 1, chain id 84257, verifying contract 0x43a6fd60c7ccef557c32a03fb2b75f5b93fe593a (the OracleVerifier). The domain type is EIP712Domain(string name,string version,uint256 chainId,address verifyingContract), and domainSeparator = keccak256(abi.encode(keccak256(domainType), keccak256("TickrOracle"), keccak256("1"), chainId, verifyingContract)).
  • The header type is SnapshotHeader(uint16 protocolVersion,uint32 configVersion,bytes32 configHash,uint64 writerEpoch,uint64 sequence,uint64 generatedAtUs,uint64 expiresAtUs,uint8 feedCount,bytes32 feedsRoot). The struct hash is keccak256(abi.encode(keccak256(headerType), the nine header fields)), and the digest is keccak256(0x1901 ‖ domainSeparator ‖ structHash).
  • The leaf type is FeedLeaf(bytes32 feedId,uint128 priceWad,uint64 observedAtUs,uint8 sourceMask,uint8 receiveOnlyMask,uint8 status,uint16 dispersionBps,uint32 reasonFlags). The leaf hash is keccak256(keccak256(abi.encode(keccak256(leafType), the eight leaf fields))). The second keccak256 stops a leaf from passing as an inner node.
  • Encode each field as one 32-byte ABI word, in the order of its type string. In the JSON, 64-bit and wider integers are decimal strings, and status is a name: VALID is 0, UNSAFE is 1 and HALTED is 2.
  • The tree has 32 slots. The real leaves, sorted by feedId as unsigned 32-byte numbers, fill slots 0 to feedCount − 1. Padding fills the other slots: slot i holds keccak256(keccak256(abi.encode(keccak256(paddingType), configHash, i))), where the padding type is TickrPadding(bytes32 configHash,uint8 slot) and i is the slot number. You need the padding only to rebuild the whole tree.
  • Every proof has exactly five sibling hashes. Start from the leaf hash and take each sibling in order. Join the two 32-byte values with the smaller one first, compared as unsigned numbers, and hash them: keccak256(min(a, b) ‖ max(a, b)). After five steps the result must equal header.feedsRoot. This is OpenZeppelin's MerkleProof rule.

Steps

  1. Read the OracleAdmin. Refuse to act while isHalted() or isRevoked() is true, or while activeSigner() is zero or differs from the pinned signer. Then check that protocolVersion is 1, and that writerEpoch, configHash and configVersion match activeEpoch(), configHash() and configVersion().
  2. Recompute the digest from header under the domain above and compare it with digest.
  3. Recover the signer with ecrecover(digest, v, r, s) and compare it with the pinned signer. digest is the final EIP-712 hash, so add no \x19Ethereum Signed Message prefix. signature is 65 bytes in the order r, s, v; v is 27 or 28, and s must be low. A recovered signer means nothing without step 2, because only the digest binds it to this header.
  4. Hash each leaf and fold it with its proof as above. The result must equal header.feedsRoot.
  5. Check every leaf the way the verifier's _validLeaf does, because the verifier refuses a batch that holds one bad leaf. isFeed(feedId) must be true, and status must be VALID, UNSAFE or HALTED. sourceMask may use only bits 0 to 3 and must be a subset of allowedSourceMask(feedId). receiveOnlyMask must be a subset of sourceMask. reasonFlags may use only bits 0 to 10, and when bit 5 (dispersion saturated) is set, dispersionBps must be 65535. A leaf that is not VALID must have priceWad and observedAtUs both zero. A VALID leaf must have a non-zero priceWad and at least two bits set in sourceMask, and its observedAtUs must be within 500 ms of generatedAtUs. Then use a feed's price only when its status is VALID, as getUsablePrice does. An UNSAFE or HALTED leaf makes only its own feed unusable, so the other feeds in the report stay usable. Read allowedSourceMask from the OracleAdmin, because the copy in /v1/feeds is unsigned advice.
  6. Reject the header unless expiresAtUs equals generatedAtUs + 3_000_000. For each feed you use, act only while generatedAtUs / 1e6 ≤ block.timestamp (with the left side rounded down) and block.timestamp is below the deadline ceil(min(expiresAtUs, observedAtUs + 3_000_000) / 1e6). Off chain, use the current Unix time in seconds as block.timestamp. labels and onchainRejectAtSec are unsigned advice, so never use them in place of this check.

Optional: the oracle adapter (batch-bound reads)

Status: ready, not enabled. The oracle adapter is deployed and bound to the verifier. No gateway is enabled on it, so its price read returns SnapshotMismatch for every priced operation class. A gateway is enabled on request.

The oracle adapter is optional. The OracleVerifier and the feed adapters do not depend on it or on any gateway. A consumer that only reads the latest price uses the OracleVerifier or the feed adapters above and needs no gateway.

What a gateway is

A gateway is an address that the adapter's admin enables with setGateway. It is the service that settles a batch of actions. Through admitBatch it hands the adapter the signed report that the batch must use, together with the batch's action IDs.

When it can help

  • Several trades settled together, or one account with positions in more than one feed. crossMarginPrices prices 1 to 32 feeds that the gateway supplies, all from the one admitted report. It covers only the feeds supplied, and cannot add a position that was left out.
  • One report per action. admitBatch binds each action ID to the admitted report once; an ID that is already bound reverts with ActionReplay. requireActionBound then checks that the bound report is still the OracleVerifier's latest.
  • Without it, two reads of the OracleVerifier a moment apart can come from two different reports, because a new report can arrive between them.

If your services do not settle trades on-chain this way, the oracle adapter does not apply.

How it serves

  • The TickrOracleAdapter is 0xd50291afd5fb60dd120b71fd341451413d5c450d.
  • priceFor(feedId, op) and crossMarginPrices(feedIds, op) take an operation class. Fill is never priced: it reverts with OperationNotPriced before any other check.
  • They answer only for the report that an enabled gateway admitted, and only while that report is still the OracleVerifier's latest. They check, in order: that a latest report exists (else the OracleVerifier's NoCanonicalReport), that the OracleAdmin is neither halted nor revoked (else Halted), and that the admitted report is the latest (else SnapshotMismatch).
  • On a current admitted report, a feed can still revert with MissingFeed, Halted (a HALTED leaf), UnsafeCollateral (every priced class rejects UNSAFE), FutureReport or ReportExpired.
  • A report that the publisher sends straight to the OracleVerifier becomes the latest there, but it is not admitted to the adapter. The adapter's reads then revert with SnapshotMismatch until the gateway admits that report.
  • To enable a gateway, the adapter's admin calls setGateway with the gateway's address, and the OracleAdmin's admin grants the adapter the publisher role. Without that role the OracleVerifier refuses the admission with UnauthorizedGateway.

The USDT switch of 2026-11-26 and the window

In the USDT switch of 2026-11-26 the feeds moved to USDT quotes: BTC/USDT and ETH/USDT replace BTC/USDC and ETH/USDC, with new feed IDs. The contracts were then redeployed at the latest code. The window below means the redeploy window of that day: the halt of the old OracleAdmin, the switch of the API host, and the resume on the new OracleAdmin. The tables above name the new contracts and feed IDs.

The USDT switch of 2026-11-26 changed the config version and the config hash. Read both from the OracleAdmin, configVersion() and configHash(), as step 1 of Verify a report says, never from a saved copy.

After the window:

  • The API no longer serves the content of a report of before the window.
  • A request for a position of before the window never returns the old report. It answers absent or with the new stack's report, by what the new store holds at that position, so an absent answer is no sign of old history.
  • Positions (writer epoch and sequence) and AggregatorV3 round IDs start again at epoch 1, sequence 1. A reused position names a report of the new stack. It can match the old report at that position in protocol version, config hash, feed count, feed IDs and even leaf content. What always differs is the signing domain's verifying contract, and with it the signed digest and the signature. Tell the two stacks apart by the signing domain, not by comparing fields: recompute the digest with the OracleVerifier in the table above, as Verify a report says, and a report of the old stack does not match.
  • A WebSocket client that resumes with a cursor of before the window never gets a report of before the window, and no answer marks the cursor as old. The general resume frames are in the WebSocket reference. For a cursor of before the window, the answer depends on where it falls in the new store:
    • The new store is empty: BackfillUnavailable with reason empty_journal, then the latest report as a snapshot frame only if one exists, then live. Do not wait for a report that may not come.
    • The cursor is below the new store's oldest kept report, the replay is over its budget, or the history read does not reach the new head: BackfillUnavailable, then the current report as a resync frame only if one exists, then live.
    • The cursor equals the new head: live only, with no replayed report.
    • The cursor falls inside the new store: a replay of the new stack's reports after it as replay frames, then live.
    • The cursor is ahead of the new head: InvalidSubscription, and the connection closes.
    • The store or its history fails a check, or the source is unavailable: NoUsableReport, with a reason such as invalid_window, invalid_history_order, invalid_report, source_unavailable or state_unavailable; a standby server can also answer lease_activation_pending or parked. The subscription is dropped and the connection stays open; subscribe again.
    • These cases follow the server's resume code (the oracle API's replay.rs, initialize and backfill); any other answer of that code path can also come.
    A replayed report that fails its check is an error to the client. A latest report that fails its check is logged and not sent; the server sends its last accepted report instead, if it has one, and that report is always one of the new stack. A long replay can also end with a SlowConsumer close, as on any subscription.
  • The old stack also ran at writer epoch 1. So a client that compares positions (writer epoch, then sequence) to find the newer report treats new reports as old until the new sequence passes the old one.
  • Drop every stored position, cursor and round ID from before the window, and subscribe without resume.
  • Replace the BTC/USDC and ETH/USDC feed IDs in every saved subscription with the BTC/USDT and ETH/USDT feed IDs in the table above. A subscribe frame that names a retired feed ID gets UnknownFeed, and that subscription does not start.
